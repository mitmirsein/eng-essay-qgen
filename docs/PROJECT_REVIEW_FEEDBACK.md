# Eng-Essay-QGen 프로젝트 점검 및 고도화 제안

- 점검일: 2026-08-02
- 중점: 강사 편의성, 교안 품질 상세화 및 고도화
- 범위: 스킬, Jinja 프롬프트, PDF 렌더러, 실제 문제지·교안·채점 산출물
- 구현 핸드오프: [P0·P1·P2 세부 구현 계획](P0_P1_P2_IMPLEMENTATION_HANDOFF.md)

## 1. 종합 평가

프로젝트의 기능 방향과 모듈 구분은 좋지만, 현재 상태는 완성된 전자동 수업 파이프라인보다는 문제 생성기와 간단한 정답·채점 메모 생성기의 성격이 강하다.

특히 교안 스킬은 45분 수업용 지도안을 목표로 하지만, 실제 산출물은 대부분 20줄 안팎이며 수업 흐름, 발문, 학생 활동, 예상 반응, 오개념 대응, 수준별 지원이 빠져 있다. 따라서 강사가 바로 수업에 활용하려면 상당한 추가 편집이 필요하다.

| 영역 | 평가 | 주요 판단 |
|---|---:|---|
| 문제 생성 다양성 | 3.5/5 | 유형·학년·수준별 생성 기반이 좋음 |
| 강사 편의성 | 2/5 | 탐색, 수정, 일괄 처리, 수업 준비 지원이 부족 |
| 교안 상세도 | 1.5/5 | 모범답안과 채점 메모 수준에 가까움 |
| 조건·답안·루브릭 정합성 | 2/5 | 실제 샘플에서 조건 위반 확인 |
| 자동 품질검수 | 1.5/5 | 보안 검사는 있으나 교육적·수치적 검증이 약함 |
| PDF 완성도 | 2/5 | 시험지와 교안 렌더링이 분리되지 않음 |
| 확장 가능성 | 4/5 | 스킬·템플릿 구조라 고도화 기반은 좋음 |

## 2. 잘된 점

1. 문제 생성, 검수, 교안, 채점, 첨삭을 역할별 스킬로 분리한 구조는 확장성이 좋다.
2. 학생용 문제지에서 모범답안과 루브릭을 분리하려는 Format Security 방향은 타당하다.
3. 이미지 답안의 HITL 확인은 인식 오류로 인한 부당한 감점을 방지하는 좋은 안전장치다.
4. [적응형 문제 프롬프트](../templates/question_prompt.j2)는 장르, 학년, 유형에 따라 조건을 조절하려는 기반이 있다.
5. [essay-coach 스킬](../skills/slash-essay-coach/SKILL.md)은 오류와 표현 개선을 구분하고 학생의 의도를 보존한다는 점에서 형성평가 가치가 높다.
6. 전용 PDF 도구와 수준별 문항 생성은 장기적으로 교사용 패키지 자동화로 발전시키기 좋은 기반이다.

## 3. 핵심 발견사항

### 3.1 교안 생성 계약과 실제 산출물의 불일치

[lesson-plan 스킬](../skills/slash-lesson-plan/SKILL.md)은 다음 여섯 영역을 요구한다.

1. 수업 개요와 교육과정 매핑
2. 주요 어휘, 핵심 문법, 내용 흐름
3. 조건별 문제 풀이 지도 전략
4. 교사용 모범답안
5. 채점 기준과 배점표
6. 교사용 수업 스크립트

그러나 실제 교안은 주로 성취기준, 모범답안, 간단한 지도 팁, 루브릭만 제공한다. 현재 `*_lesson.md` 산출물 전체에서 다음 항목을 찾을 수 없다.

- 수업 목표
- 준비물과 소요 시간
- 도입, 전개, 정리
- 교사 활동과 학생 활동
- 예상 학생 답변
- 오개념 및 오류 대응
- 형성평가와 출구 티켓
- 주요 어휘와 지문 분석
- 교사용 수업 대본

현재 교안은 수업 지도안보다 교사용 정답 및 채점 가이드에 가깝다.

### 3.2 모범답안의 조건 미충족

다음과 같은 정합성 오류가 실제 산출물에서 확인된다.

- [AI 윤리 문제](../output/essay-questions/20260801_123100-type2-ai_ethics.md)는 50~70단어를 요구한다.
- [AI 윤리 교안](../output/lesson-plans/20260801_123200-type2-ai_ethics_lesson.md)의 기본 답안은 40단어다.
- 같은 교안의 확장 답안은 51단어라고 표기되어 있으나 실제 계산은 48단어다.
- [수준별 Level 3 문제](../output/essay-questions/20260801_133000-diff-climate_change.md)는 40~60단어를 요구한다.
- [수준별 교안](../output/lesson-plans/20260801_133000-diff-climate_change_lesson.md)의 Level 3 답안은 35단어다.

모범답안은 교사가 학생에게 제시하거나 채점 기준으로 사용할 수 있으므로, 이런 오류는 자동 생성 결과의 신뢰도를 크게 떨어뜨린다.

### 3.3 문제, 루브릭, 교안의 원본 분산

현재 데이터 흐름은 서로 충돌한다.

- [question_prompt](../templates/question_prompt.j2)는 학생용 출력에 루브릭을 포함한다.
- [essay-review](../skills/slash-essay-review/SKILL.md)는 학생용 문제지에 루브릭이 있으면 Fail 처리한다.
- [essay-grade](../skills/slash-essay-grade/SKILL.md)는 문제지 파일에 루브릭이 포함되어 있다고 전제한다.
- 현재 학생용 문제지에서는 보안 규칙에 따라 루브릭이 제거되어 있다.

이 구조에서는 채점 단계가 루브릭을 찾지 못하거나, 교안 생성 단계에서 원래 루브릭과 다른 기준을 재생성할 수 있다.

문제, 조건, 루브릭, 모범답안, 교안은 하나의 내부 구조화 파일에서 파생해야 한다.

```text
assessment.json
├── metadata
├── passage
├── task
├── conditions[]
├── rubric[]
├── model_answers[]
├── lesson_plan
└── qa_results
```

학생용 PDF와 교사용 PDF는 이 파일의 서로 다른 뷰로 렌더링하는 것이 안전하다.

### 3.4 교안 품질 검수 부족

현재 검수는 학생용 정답 노출 방지와 교사용 답안·루브릭 존재 여부에 집중되어 있다. 다음 자동 검증이 추가되어야 한다.

- 모범답안 실제 단어 수
- 필수 문법 사용 횟수
- 금지된 연속 5단어 복사
- 모든 내용 조건 충족
- 루브릭 총점 일치
- 조건과 루브릭의 일대일 대응
- 반복 감점과 이중 감점 방지
- 교안 필수 섹션 충족
- 성취기준의 정확성
- 수업 활동과 평가 목표의 정렬

학생용 보안 검수와 교안 품질 검수는 별도 모드로 분리하는 편이 명확하다.

### 3.5 적응형 로직과 하드코딩된 지시의 충돌

[question_prompt](../templates/question_prompt.j2)는 고정 조건을 사용하지 말라고 지시한다. 반면 [essay-qgen 스킬](../skills/slash-essay-qgen/SKILL.md)은 인용, 상징 추론, 창의적 사고라는 type1 중심 조건을 고정한다.

[lesson-plan 스킬](../skills/slash-lesson-plan/SKILL.md)도 거울의 상징과 5단어 인용 같은 특정 유형의 지도법을 예시가 아니라 기본 구조로 사용한다.

교안 지도 전략은 문제 유형에 따라 달라져야 한다.

- type1: 근거 찾기, 인물 심리, 상징 추론
- type2: 핵심 정보 표, 비교·대조, 요약, 패러프레이징
- type3: 독자·목적·문체, 주장과 근거, 실용문 형식

### 3.6 교안에 부적합한 PDF 렌더링

[make_exam_pdf.py](../tools/exam-pdf/make_exam_pdf.py)는 모든 문서를 2단으로 감싸고, [exam-preamble.tex](../tools/exam-pdf/exam-preamble.tex)은 이름란과 총점이 있는 시험지 헤더를 사용한다.

이로 인해 다음 문제가 발생한다.

- 교안에 이름란과 총점이 표시됨
- 수업 순서표와 긴 설명에 부적합한 2단 레이아웃
- 이모지가 네모 문자로 깨짐
- 루브릭 분리 이후 학생용 문제지 총점이 0점으로 표시됨
- 누락 문자가 발생해도 PDF 빌드가 성공으로 종료됨

렌더링 프로필을 분리해야 한다.

```text
--profile exam       2단, 이름란, 총점
--profile teacher    1단, 목차, 페이지 구분, 메모 영역
--profile feedback   1단, 학생 식별자, 점수 및 첨삭
```

### 3.7 검증 가능한 성취기준 데이터 부재

교안은 NCIC 참조를 요구하지만 저장소에는 검증된 성취기준 코드표가 없다. 실제 교안도 `중3~고1`, `고1~2`처럼 넓은 범위와 자연어 설명만 제공한다.

교안에는 다음 정보가 필요하다.

- 학교급과 대상 학년
- 성취기준 코드
- 기준의 핵심 수행 동사
- 이번 활동에서 확인할 학습 증거
- 문항 조건 및 루브릭과의 연결
- 선정 이유

검증된 `references/curriculum-2022.json`을 두고 존재하는 코드만 선택하도록 제한하는 것이 안전하다.

### 3.8 지문 검수 단계 부재

[auto-essay](../skills/slash-auto-essay/SKILL.md)는 지문 생성 후 별도 검수 없이 문제 출제로 넘어간다.

[Snow White 지문](../passages/20260801_120000-type1-snow_white.txt)에는 `the queen dies when she gave birth`처럼 시제가 충돌하는 문장이 있다. 이런 오류가 그대로 문제지와 교안에 들어갈 수 있다.

`/passage-review` 단계에서 다음을 검사해야 한다.

- 문법과 시제 일관성
- 학년별 어휘 및 문장 길이
- 사실성과 편향
- 복수 지문의 관점과 정보량 균형
- 문제를 풀기에 충분한 근거
- 부자연스러운 생성형 문장

### 3.9 수준별 수업 지원 부족

[수준별 교안](../output/lesson-plans/20260801_133000-diff-climate_change_lesson.md)은 세 수준의 모범답안과 루브릭만 제공한다. 현재 기능은 수준별 수업보다 서로 다른 난이도의 문제 세 개를 생성하는 데 가깝다.

실제 수준별 수업에는 다음이 필요하다.

- 공통 학습 목표
- 진단 기준과 학생 배치 방법
- Level 1 문장 틀, 단어 은행, 근거 표시
- Level 2 문장 결합과 조직자
- Level 3 확장 질문과 심화 표현
- 그룹 이동 기준
- 공통 정리와 출구 티켓

### 3.10 강사 운영 기능과 개인정보 관리 부족

- 배치 채점의 학생별 순차 승인은 안전하지만 대규모 학급에서는 오래 걸린다.
- 전체 학생의 공통 오류와 재수업 대상을 요약하지 않는다.
- CSV 성적표, 루브릭 분포, 오류 유형 통계가 없다.
- 채점·첨삭 결과가 교안과 같은 폴더에 저장되어 탐색이 어렵다.
- 학생 이름이 포함된 결과물이 Git에 추적될 수 있다.

권장 구조는 다음과 같다.

```text
output/lesson-plans/guides/
output/lesson-plans/grading/
output/lesson-plans/coaching/
output/lesson-plans/class-insights/
```

학생 자료는 기본적으로 Git에서 제외하고 익명 ID를 사용해야 한다.

## 5. 구현 우선순위

### P0: 정확성과 신뢰성

1. `assessment.json`을 단일 원본으로 도입한다.
2. 단어 수, 문법 조건, 연속 복사, 총점, 조건 대응 validator를 추가한다.
3. 학생용, 교사용, 채점용 문서를 같은 데이터에서 생성한다.
4. 학생 보안 검수와 교안 품질 검수를 분리한다.
5. PDF의 exam, teacher, feedback 프로필을 분리한다.
6. `Missing char > 0`, 학생 총점 0, 모범답안 조건 미충족 시 빌드를 실패 처리한다.
7. 지문 검수 단계를 추가한다.

### P1: 교안 품질

1. 독립적인 `templates/lesson_plan_prompt.j2`를 추가한다.
2. 교안 v2 구조를 출력 계약으로 지정한다.
3. 검증된 교육과정 성취기준 데이터를 추가한다.
4. 문제 유형별 지도 전략을 분리한다.
5. 최소 답안, 우수 답안, 경계 답안과 채점 앵커를 생성한다.
6. 수준별 문장 틀, 그래픽 조직자, 예상 오개념을 제공한다.

### P2: 강사 편의성

1. `teacher_profile.yaml`로 학교명, 학년, 수업 시간, 채점 정책, 출력 형식을 저장한다.
2. 전체 산출물을 보여주는 인덱스나 HTML 대시보드를 생성한다.
3. 배치 HITL 승인표와 중단 후 재개 기능을 추가한다.
4. 성적 CSV, 루브릭 분포, 공통 오류 및 재수업 그룹을 출력한다.
5. DOCX 등 수정 가능한 교사용 출력을 지원한다.
6. 교안 전체가 아니라 특정 섹션만 재생성할 수 있게 한다.
7. 학생 개인정보 산출물을 Git에서 제외한다.

## 6. 품질 게이트 권장 기준

최종 패키지는 다음 조건을 모두 통과해야 한다.

- 학생용 파일에 모범답안과 루브릭이 없음
- 교사용 파일에 검증된 답안과 루브릭이 있음
- 답안 단어 수가 문제 조건 범위에 포함됨
- 요구 문법과 내용 조건이 모두 충족됨
- 금지된 연속 복사 규칙을 위반하지 않음
- 루브릭 합계가 문항 총점과 일치함
- 모든 조건에 대응하는 루브릭 항목이 있음
- 성취기준 코드가 내부 기준 데이터에 존재함
- 교안 v2 필수 섹션이 모두 존재함
- 학생용 PDF 총점이 0보다 큼
- 교안 PDF에 이름란과 시험 총점이 없음
- PDF Missing character와 Overfull 오류가 허용 기준 이내임

## 7. 추가 기술 정리

1. 기존 스킬 중 `essay-coach`를 제외한 스킬은 공식 validator에서 `status`, `version` frontmatter 때문에 실패한다.
2. Jinja 템플릿을 실제로 로드하고 실행하는 런타임 코드가 없고, 에이전트의 서술형 지시 수행에 의존한다.
3. 자동 테스트, golden fixture, CI, 명시적인 의존성 설정이 없다.
4. [fix_rubric_split.py](../bin/fix_rubric_split.py)는 특정 이모지 제목과 파일명에 의존하여 정규 파이프라인으로 사용하기에는 취약하다.

## 8. 최우선 권고

교안 프롬프트를 먼저 길게 만드는 것보다 `assessment.json + 자동 validator + 학생/교사 뷰 분리`를 먼저 구축해야 한다.

이 기반이 없으면 교안이 더 상세해지더라도 잘못된 모범답안과 루브릭이 더 그럴듯하게 포장될 위험이 있다. 단일 원본과 품질 게이트를 구축한 다음 교안 v2와 강사 편의 기능을 확장하는 순서가 가장 안전하다.
